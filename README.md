# BomBound
## 制作背景
Game A Week(1週間ゲーム制作)に挑戦し、「1週間で企画から完成までもっていくこと」
を目標に制作しました

## 概要
プレイヤーは交代で爆弾のボタンを押し、爆弾を爆発させないように立ち回ります。
爆発ラインは見えず、さらに「神のお告げ」による真実・嘘・不幸イベントが発生するため
運と心理戦が重要になります。

## 制作期間
・個人製作
・制作期間：1週間
・開発環境：Unity
・使用言語：C#

## ゲームルール
１．プレイヤーはボタンを押して爆弾を進行させる
２．1回以上押した後にターン終了が可能
３．爆発ラインは毎ゲームランダム
４．爆弾を爆発させたプレイヤーの負け

## ゲームモード
### CPU対戦
CPUと対戦するモードです。

### 2人対戦
ローカルで2人対戦を行うモードです

## 実装内容
・タイトル画面
・CPU対戦モード
・2人対戦モード
・ターン管理システム

・神ポイントシステム

## プログラム設計

### ターン管理システム
現在の手番を管理し、プレイヤーとCPUの行動を
切り替える仕組みを実装しました。

また、1回もボタンを押さずにターン終了できないよう
制御し、ゲームルールをプログラム上で保証しています。

### ランダム爆発システム
ゲーム開始時に爆発ラインをランダムで決定し、
プレイヤーには公開しない仕様としました。

ボタンが押されるたびに内部カウントを加算し
爆発ラインに到達すると爆発処理が実行されます。

### CPU対戦処理

CPU手番では一定時間ごとに行動を選択するよう実装しました。

押す・交代する行動をランダムに選択することで、
毎回異なる展開になるように設計しています。

### 神ポイントシステム
ボタンを押すことで神ポイントを獲得できる仕組みにしました。
神ポイントが一定数以上ある場合のみ神のお告げを利用できるようにし
UIとも連動させています。

### 神のお告げシステム
神ポイントを消費することでお告げを発動できます。

・真実のお告げ
・嘘のお告げ
・不幸イベント

真実のお告げでは、現在の状況から爆発までの危険度を判定し
段階的なヒントを表示するようにしました。



## 工夫した点

### 神のお告げシステム
単純な運任せのゲームにならないよう、真実・嘘・不幸イベントを組み合わせた
神のお告げシステムを実装しました。

プレイヤーは得た情報を信じるかどうかを判断する必要があり、
心理戦が発生するように設計しています。

### 神ポイントシステム
ボタンを押すほど情報を得やすくするため、

・安全に立ちまわる
・リスクをとって情報を集める

という選択が生まれるように工夫しました。

### ランダム性と心理戦

爆発ラインを非公開かつランダムに設定することで、
毎回異なる展開になるように設計しました。

プレイヤー同士の読みあいが発生することを重視しています。

## 学んだこと
1週間という短い制作期間のなかで、コアとなる
ゲームループを優先して実装する重要性を学びました。
また、単純な運要素だけでなく、プレイヤーが判断する余地を作ることで
ゲーム性が向上することを実感しました。
